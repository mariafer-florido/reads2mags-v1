00. Preparación del proyecto

01. Visual Studio Code: conexión al servidor de prácticas

Duración sugerida: 45 minutos (10 min de introducción y 35 min de práctica).

¿Qué aprenderemos?

Al terminar esta actividad podrás:

  1. Distinguir tu computadora, VS Code y el servidor donde están los datos y programas del curso.
  2. Abrir una sesión SSH desde Visual Studio Code, explorar archivos y utilizar una terminal remota.
  3. Registrar en una bitácora las comprobaciones mínimas de tu entorno de trabajo.

Pregunta guía: ¿dónde se ejecuta realmente un comando y cómo podemos comprobarlo?

01.1 Nuestro entorno de trabajo

En las siguientes prácticas utilizaremos lecturas metagenómicas del pozol para seguir el flujo que va del control de calidad al ensamblaje, la recuperación de MAGs y su interpretación. No necesitamos descargar los metagenomas a nuestras computadoras para analizarlos.

  Visual Studio Code (interfaz y editor)
           |
           | conexión SSH
           v
SERVIDOR DEL CURSO
  archivos, terminal, herramientas y resultados

Visual Studio Code (VS Code) es un editor de código con explorador de archivos y terminal integrada. La extensión Remote - SSH permite abrir una carpeta remota y trabajar con sus archivos desde la interfaz de nuestra computadora. No es lo mismo que el programa Visual Studio. Tampoco sustituye al servidor, a Linux ni a las herramientas bioinformáticas. Documentación oficial.

01.2 Preparación: antes de conectarte

En tu computadora:

  1. Instala Visual Studio Code y ábrelo.
  2. Ve a Extensions / Extensiones (icono de cuatro bloques) y busca Remote - SSH. Instala la extensión publicada por Microsoft (identificador ms-vscode-remote.remote-ssh).
  3. Comprueba que tienes un cliente SSH: abre Terminal en macOS o Linux, o PowerShell en Windows, y escribe ssh -V.
  4. Ten a mano los datos de conexión asignados individualmente por el equipo docente (usuario, dirección del servidor y método de autenticación). Se enviarán por un canal privado; no están publicados en esta página.

Importante: no compartas contraseñas, llaves privadas ni capturas donde se vean credenciales. Si aún no tienes cuenta o acceso al servidor, sigue la demostración y avisa al equipo docente; no inventes una dirección ni uses la cuenta de otra persona.

01.3 Comprobar la conexión SSH

Este primer comando se ejecuta en una terminal de tu propia computadora, no en la terminal de VS Code conectada al servidor:

ssh USUARIO@SERVIDOR

Sustituye USUARIO y SERVIDOR por los datos que recibiste. Si se te proporcionó un puerto diferente al habitual, utiliza ssh -p PUERTO USUARIO@SERVIDOR.

  • La primera vez podría aparecer un aviso sobre la huella digital (fingerprint) del servidor. Compárala con la que proporcione el equipo docente antes de aceptarla.
  • Al escribir una contraseña, es normal que no aparezcan caracteres en pantalla.
  • Si te conectaste correctamente, puedes cerrar esa primera sesión con exit y continuar en VS Code.

01.4 Conectarte desde VS Code

  1. Abre la Paleta de comandos: F1 o Ctrl + Shift + P (Windows/Linux), Cmd + Shift + P (macOS).
  2. Escribe y selecciona Remote-SSH: Connect to Host….
  3. Elige el servidor guardado o escribe USUARIO@SERVIDOR (los mismos datos de la prueba anterior).
  4. Completa la autenticación cuando VS Code lo solicite. La primera conexión puede tardar mientras configura los componentes remotos.
  5. Comprueba que la barra de estado identifica una conexión SSH al servidor previsto.

Si aparece una ventana nueva, es normal. Lo esencial es que la sesión actual indique que estás conectado al host remoto.

01.5 Abrir la carpeta y orientarte en la terminal

Ya conectado al servidor, usa File / Archivo → Open Folder / Abrir carpeta y selecciona la ruta que indique el equipo docente. En algunos entornos del curso se ha utilizado ~/reads2mags_pozol, pero esa ruta no está garantizada para todas las cuentas.

Ahora abre Terminal → New Terminal / Nueva terminal y ejecuta estos comandos dentro de VS Code conectado por SSH:

whoami       # ¿Con qué cuenta entré?
hostname     # ¿En qué computadora se ejecutan mis comandos?
pwd          # ¿En qué directorio estoy?
ls -lah      # ¿Qué archivos, tamaños y permisos puedo ver?

Comprueba tus respuestas: hostname debería corresponder al servidor del curso; whoami, a tu usuario asignado; y pwd, a tu carpeta actual. Una terminal local y una terminal remota pueden verse iguales: estos comandos permiten distinguirlas.

Para identificar tipos de archivos del flujo metagenómico, revisa el listado que muestre el equipo:

Extensión ¿Qué representa en este taller?
.fastq / .fastq.gz Lecturas de secuenciación y sus calidades; pueden venir en pares R1/R2.
.fasta / .fa Secuencias, como contigs o genomas reconstruidos, sin valores de calidad por base.
.tsv / .csv Tablas de resultados y metadatos.
.sh / .R / .Rmd Comandos, scripts o análisis documentados.
.html Informes y reportes que podemos consultar desde el navegador.

No abras ni copies FASTQ grandes sólo para comprobar que existen. Por ahora basta con reconocer el nombre y el tipo de archivo; el capítulo 03 explica cómo evaluar su calidad.

01.6 Tu primera bitácora (en una carpeta personal)

Una práctica reproducible necesita dejar constancia de lo que hicimos. No modifiques el proyecto original ni los resultados compartidos. Primero crea una carpeta en tu propio espacio de usuario:

mkdir -p "$HOME/curso_metagenomica_2026/bitacora"
cd "$HOME/curso_metagenomica_2026/bitacora"
touch 00_entorno.md
ls -lh 00_entorno.md

Desde el explorador de VS Code, abre 00_entorno.md y escribe una nota como ésta (sin incluir credenciales ni datos personales de otros participantes):

# Mi entorno de trabajo

- Fecha:
- ¿VS Code está conectado al servidor?: Sí / No
- ¿Identifiqué mi carpeta de trabajo?: Sí / No
- ¿Puedo reconocer un archivo de datos y uno de resultados?: Sí / No
- Duda o problema que debo resolver:

Guarda el archivo (Ctrl + S o Cmd + S). El resultado de esta actividad es una bitácora breve que podrás seguir usando en las prácticas, no una copia de los datos originales.

01.7 Si no funciona: diagnóstico sin modificar el servidor

Síntoma ¿Qué comprobar primero?
La terminal dice ssh: command not found Estás en tu equipo local: revisa la instalación del cliente SSH.
No se puede localizar el host o expira la conexión Verifica dirección, conexión de red y si el equipo docente indicó utilizar VPN.
Permission denied Revisa el usuario y el método de autenticación asignados; no publiques la contraseña.
VS Code se conecta, pero no abre la carpeta Confirma la ruta y los permisos de tu cuenta; no uses sudo ni cambies permisos de carpetas compartidas.
VS Code falla, pero el comando ssh sí funciona Revisa View → Output → Remote - SSH y comparte sólo el error relevante, sin credenciales.

Alternativa durante la clase: si la extensión no conecta, puedes seguir temporalmente los ejemplos con una terminal SSH convencional. El equipo docente te ayudará a resolver el acceso gráfico después. No instales herramientas ni ejecutes trabajos pesados en el nodo de acceso por tu cuenta.

02. Organización de el entorno de trabajo

Durante cualquier proyecto bioinformático es importante tener orden del directorio de trabajo y los procesos que se ejecutan.

Una buena práctica es crear un directorio principal del proyecto que contenga subdirectorios de trabajo, la estructura puede ser la siguiente:

data Directorio donde se almacenan los datos que sirven como
entrada inicial para comenzar el proyecto.

results Directorio en el que se almacenan los resultados obtenidos
en cada paso del análisis.

scripts Directorio en el que se almacenan los scripts generados en cada paso del análisis.

outs Directorio en el se direccionan las salidas del stdout a un archivo log de cada proceso.

README.md Archivo README principal en el que se explica el objetivo
del proyecto, el flujo de trabajo, los requistos de
ejecución, estructura del repositorio, los resultados obtenidos y sus conclusiones.

04. Advertencias

La presente práctica sólo es una representación del flujo de trabajo para el análisis metagenómico, sin embargo, no sustituye los manuales de cada programa y el flujo puede variar dependiendo del tipo de datos y pregunta de investigación, de hecho para fines del taller, con frecuencia se utilizan las líneas de comando más simples para eficientar tiempo y recursos, tómalo en cuenta.

Cada programa tiene una ayuda y un manual de usuario, es importante revisarlo y conocer cada parámetro que se ejecute. En terminal se puede consultar el manual con el comando man y también se puede consultar la ayuda con -h o --help, por ejemplo fastqc -h.

Important

🧠 Para tenerlo presente

En bioinformática cualquier línea de comandos generará un resultado, de ahí a que esos resultados sean correctos puede haber una gran diferencia.

En cada paso:

  • Detente a revisar la información de cada programa, lee el manual y la ayuda

  • Elige los parámetros que mejor se adapten a tus datos.

  • Analiza las salidas de cada proceso y los resultados.

  • Haz varias pruebas, usa controles (positivo y negativo).

  • Visita foros de ayuda, complementa con IA.

  • Toma decisiones informadas y con argumentos sólidos.

  • Disfruta el proceso.

05. ¿Cómo abordar Proyecto Metagenómico?

En los proyectos metagenómicos el diseño experimental y el procesamiento de los datos es muy importante. El procesamiento puede abordarse de dos maneras diferentes, durante este taller veremos la forma más básica y durante la segunda parte veremos la forma avanzada.
